# 題材重複調査レポート: `replaceAll`に金額の`$`を渡し、テンプレートレンダリングが失敗する

## 調査対象

| 項目 | 内容 |
| --- | --- |
| 対象言語 | Java 21 |
| 難易度プロファイル | 実践・上級 |
| 候補題材 | `String.replaceAll`のreplacementへ`$5.00`をそのまま渡し、存在しないグループ5として解釈されてテンプレートが失敗する問題 |
| 観測可能な契約 | 既に`EUR 5.00`を成功レンダリングした状態で、`$5.00`をレンダリングしたとき、成功結果・新しい本文・成功件数2を返すべきだが、バグ状態では拒否結果・旧本文・旧成功件数が残る。 |
| 直接原因 | 正規表現のreplacement構文を持つ`replaceAll`へ、外部入力をliteral replacementへ変換せずに渡していること。 |
| カタログ更新日時 | Repository Catalog（`/home/ubuntu/repository-catalog`）は存在しなかったため更新・検証は実施不能。代替として、ユーザー指定の`tonbiattack/qiita`を取得し、Java・`replaceAll`・`quoteReplacement`・正規表現置換・置換文字列・ドル記号を本文とパスから検索した。 |
| 検索語 | `Java`, `replaceAll`, `replaceFirst`, `quoteReplacement`, `正規表現 置換`, `置換文字列`, `Illegal group reference`, `ドル記号` |

Repository Catalogが利用できなかったため、このレポートの新規性判断は指定コンテンツリポジトリを対象とします。カタログに未登録のローカル専用教材までは保証できない限界を明示します。

## 結論

**作成する。**

Javaの正規表現置換に近接する既存記事は確認できましたが、`replaceAll`の**第二引数にあるドル記号がグループ参照として解釈される**ことを直接原因として、レンダリング結果・最後の成功本文・成功件数を扱う記事・教材は見つかりませんでした。

既存のyoutube-dl記事とは、検索側でXMLエンティティを判定する問題か、置換側で外部値をliteral化する問題かが異なります。対象言語、実境界、観測契約、最小修正がいずれも独立しているため、教育上意味のある追加題材と判断しました。
